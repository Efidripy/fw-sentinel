# FW Sentinel

[English](README.md) · **Русский**

Небольшой сторож для VPN-сервера на Linux. Загружает публичные списки угроз в `nftables`, банит сканеры портов и переборщиков SSH и показывает в веб-панели, что происходит прямо сейчас.

Только стандартная библиотека Python, без сервера баз данных и контейнеров.

> **Статус: бета.** Программа отбрасывает сетевой трафик. Начинайте с режима `observe`, держите под рукой консоль провайдера и сначала прочитайте [Ограничения](#ограничения).

## Зачем

Свежий VPS с публичным адресом начинают сканировать за минуты. Обычные ответы — либо тяжёлый комплекс защиты, который не помещается на сервер с 1 ГБ, либо набор shell-скриптов, который страшно трогать: одна ошибка, и вы без доступа.

FW Sentinel построен на трёх идеях:

1. **Нельзя случайно запереть самого себя.** Правила проверяются `nft -c` до загрузки, прежняя политика сохраняется, а таймер systemd откатывает неподтверждённое изменение.
2. **Сначала посмотреть, потом блокировать.** Режим `observe` записывает, что *произошло бы*, ничего не отбрасывая.
3. **Не мешать остальному.** Используется одна таблица (`inet fw_sentinel`). VPN, веб-сервер и другие правила firewall не затрагиваются.

## Что умеет

| Возможность | Как работает |
| --- | --- |
| Списки угроз | Известные массовые сканеры, Spamhaus DROP, Blocklist.de, DShield, FireHOL, ThreatView, NERD и другие, обновление раз в сутки. Частные и служебные сети удаляются; список, внезапно накрывший слишком большую часть интернета, отклоняется. |
| ASN и страны | Блокировка выбранных автономных систем. По желанию — доступ к выбранным портам только из одной страны. |
| Автобан за скан портов | 6 разных закрытых TCP-портов за 60 с или 8 за час (медленные сканеры). |
| Порты-ловушки | Одно обращение к порту, которым вы не пользуетесь, — бан. |
| Защита SSH | Успешный вход делает адрес доверенным (по ключу на 30 дней, по паролю на 24 часа). 6 неудачных попыток за 10 минут или 10 за сутки — бан. |
| Нарастающие баны | 24 часа → 7 дней → 30 дней → 180 дней → 365 дней. Баны за ловушку и SSH начинаются с 1 часа. |
| Ручные списки | Доверенные адреса, VPN-клиенты и блокировки — по одному или пачкой. |
| Веб-панель | Живая лента, история по каждому адресу с портами и счётчиками, страна, провайдер и рейтинг злоупотреблений, управление списками и политикой. Английский и русский. |
| Переживает перезагрузку | Последняя подтверждённая политика восстанавливается при загрузке; сторож возвращает таблицу, если она пропала. |

## Как устроено

```
публичные базы ──► fw-sentinel sync ──► кэш ──► правила ──► nft -c ──► nftables (таблица inet fw_sentinel)
                                                                           │
журнал ядра ◄──────────────────────────────────────────────────────────────┘
     │
     └──► fw-sentinel monitor ──► история в SQLite, автобан ──► веб-панель (127.0.0.1:1488)
журнал sshd ───────┘
```

| Часть | Что делает |
| --- | --- |
| `fw_sentinel.py` | Командная строка, базы, генерация правил, применение и откат |
| `webui.py` | Веб-панель |
| `autoban.py` | Обнаружение сканов, ловушек и перебора SSH, сроки банов |
| `ipmeta.py`, `ipintel.py` | Страна, провайдер и рейтинг AbuseIPDB для адреса |
| `fw-sentinel-monitor.service` | Читает журнал ядра и, если включено, журнал sshd |
| `fw-sentinel-ui.service` | Запускает панель |
| `fw-sentinel-update.timer` | Ежедневное обновление баз |
| `fw-sentinel-guard.timer` | Раз в минуту проверяет, на месте ли правила |
| `fw-sentinel-restore.service` | Восстанавливает подтверждённую политику при загрузке |

## Требования

- Linux с `systemd` и `nftables`; разрабатывалось под Ubuntu 24.04, работает и на Ubuntu 26.04
- Python 3.12 или новее, только стандартная библиотека
- Права root
- Память: со всеми большими списками (около 520 000 адресов) на одном измеренном сервере ядро занимало около 70 МБ, а пик во время применения был около 290 МБ. Если свободной памяти мало, большие списки одиночных адресов пропускаются с предупреждением.

## Установка

```bash
git clone https://github.com/Efidripy/fw-sentinel.git
cd fw-sentinel
sudo bash install.sh
```

Установщик **не включает блокировки**. Он ставит службы, добавляет адрес вашей текущей SSH-сессии в доверенные и печатает логин панели (`admin`) и сгенерированный пароль; пароль лежит в `/opt/fw-sentinel/ui-token` (доступен только root).

Дальше по шагам:

```bash
sudo fw-sentinel sync        # скачать базы
sudo fw-sentinel observe     # только запись, ничего не отбрасывать
sudo fw-sentinel audit-vpn   # не попадают ли ваши VPN-клиенты под блокировку
sudo fw-sentinel enable      # включить блокировки, с таймером подтверждения
```

Перед `enable` убедитесь, что ваш статичный адрес есть в доверенных:

```bash
sudo fw-sentinel allow 203.0.113.10
```

## Веб-панель

Панель слушает только `127.0.0.1:1488`. Самый простой и безопасный вход — SSH-туннель:

```bash
ssh -L 1488:127.0.0.1:1488 root@ВАШ_СЕРВЕР
```

После этого откройте `http://127.0.0.1:1488/`.

Чтобы опубликовать панель за nginx на секретном пути, возьмите пример [`nginx/fw-sentinel-location.conf.example`](nginx/fw-sentinel-location.conf.example) и сообщите панели её адрес:

```bash
sudo env FWS_UI_BASE_PATH=/your-secret-path/ FWS_UI_PUBLIC_ORIGIN=https://panel.example.com bash install.sh
```

Путь должен состоять из латинских букв, цифр, `-` и `_`. Ограничьте этот location по IP или через VPN: панель работает от root, ограничения частоты запросов нет, открывать её всему интернету нельзя.

| Страница | Что там |
| --- | --- |
| Сводка | Режим, счётчики, защита в одно нажатие, живая лента (обновление от 0,25 до 10 с), самые отбиваемые адреса |
| Журнал IP | История по адресам: порты, счётчики, первое и последнее обращение |
| Списки IP | Активные баны по причинам, доверенные и VPN-адреса, доверенные по SSH, импорт пачкой |
| Базы угроз | Все списки с размером и временем обновления, обновление по одному, API-ключи |
| Настройки защиты | Выбор списков, автобан, порты-ловушки, защита SSH и применение |

Интерфейс по умолчанию английский; на русский переключается кнопкой в шапке.

**Применение из панели** сохраняет правила сразу, если ваш адрес (`X-Real-IP` от nginx) доверенный или не подпадает ни под одно блокирующее правило. Иначе, а также когда адрес неизвестен, у вас есть 120 секунд на подтверждение, после чего вернётся прежняя политика.

## Команды

Запуск: `sudo fw-sentinel <команда>`.

| Команда | Действие |
| --- | --- |
| `status` | Режим и счётчики |
| `sync` | Скачать и применить свежие базы |
| `observe` / `enable` / `disable` | Только запись / блокировать / удалить таблицу (аварийный стоп) |
| `ban`, `unban`, `allow`, `unallow`, `vpn-add`, `vpn-remove` `<ip>` | Ручные списки |
| `auto-unban <ip>` | Снять автоматический бан |
| `check <ip>` | В каких списках есть адрес |
| `audit-vpn` | VPN-клиенты, которых зацепил бы блокирующий список |
| `hits` | Записанные события |
| `render [--enforce]` | Показать правила, не загружая их |
| `verify-restore` | Готова ли политика пережить перезагрузку |
| `feeds-prepare`, `feeds-status` | Четыре дополнительные базы |
| `feeds-catalog-sync [id]`, `feeds-catalog-status` | Большой дополнительный каталог |
| `abuse-key-set` | Сохранить API-ключ AbuseIPDB |
| `provider set\|disable\|status [id]` | Ключи других поставщиков |
| `menu` | Текстовое меню |

## Настройки

Значения по умолчанию — в [`config.json`](config.json), при первой установке копируются в `/opt/fw-sentinel/config.json`; обновление только добавляет новые ключи. Большинство из них переключается в панели.

| Ключ | Смысл |
| --- | --- |
| `ssh_ports`, `wan_interfaces` | Определяются при установке, проверьте |
| `vpn_ports` | Порты, на которых работает VPN |
| `scanner_enabled`, `asn_enabled`, `geo_enabled` | Списки сканеров, `asn.txt`, фильтр по стране |
| `extra_threat_feeds_enabled`, `advanced_feed_pack_enabled` | Дополнительные и большие списки |
| `autoban_enabled`, `autoban_trap_ports` | Автобан за скан и порты-ловушки |
| `autoban_exclude_tcp_ports`, `autoban_exclude_udp_ports` | Порты, которые не считаются сканированием |
| `ssh_watch_enabled` | Доверие по SSH и бан за перебор (нужны автобан и `enable`) |
| `event_retention_days` | Сколько хранить историю |

Порты работающих служб, SSH и VPN не считаются сканированием независимо от списков исключений.

## API-ключи

Все блокировки работают без ключей. Ключ AbuseIPDB добавляет его список и рейтинг в панели. Панель умеет хранить ключи и других сервисов, но **сейчас подключён только AbuseIPDB**. Ключи остаются на вашем сервере.

## Обновление, аварийный стоп, удаление

Обновление: `git pull && sudo bash install.sh`. Настройки, списки, история и пароль сохраняются.

Аварийный стоп из SSH или консоли провайдера:

```bash
sudo fw-sentinel disable
```

Удаление:

```bash
sudo fw-sentinel disable
sudo systemctl disable --now fw-sentinel-ui fw-sentinel-monitor fw-sentinel-restore fw-sentinel-update.timer fw-sentinel-guard.timer
sudo rm -r /etc/systemd/system/fw-sentinel-* /usr/local/lib/fw-sentinel /usr/local/sbin/fw-sentinel
sudo rm -r /opt/fw-sentinel   # настройки, списки и история
sudo systemctl daemon-reload
```

## Ограничения

- Публичные списки — чужие данные без фиксации версии. Широкие списки могут содержать общие (NAT, операторские) адреса настоящих пользователей. Сначала `observe` и `audit-vpn`.
- Уже установленные соединения новые правила обычно не разрывают.
- Для бана за скан достаточно SYN-пакета, поэтому подделанный адрес может подставить постороннего под бан. Открытые и служебные порты из этого бана исключены.
- Запись в журнал ограничена по частоте, поэтому при потоке пакетов счётчики показывают нижнюю оценку.
- В автотестах `nft` и `systemd` заменены заглушками. Проверяйте поведение на своём сервере.
